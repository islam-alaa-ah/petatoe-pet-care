# AM1R2 — تقرير الأثر والإصلاح

## Root Cause والأدلة

فشل تحميل اعتماديات JavaScript المطلوبة لتوليد PDF. تحققت قراءة HTTP مباشرة من أن version.json وindex.html وpwa.js وservice-worker.js وpackage.json وsha2.js وattachment-pdf.mjs والخط تطابق المصدر المنشور 18.56.145. بينما `_md.js` و`_u64.js` يرجعان 404 من GitHub Pages، ويرجعان 200 من المصدر الخام لنفس فرع main مع تطابق كامل لحزمة AM1R1.

المكتبة الأم تستورد الاسمين بشكل مباشر؛ غياب أي منهما يوقف استيراد attachment-pdf.mjs. سلوك النشر متطابق مع استبعاد Jekyll الافتراضي للأسماء التي تبدأ بـunderscore. لا يوجد في دليلنا ما يربط المشكلة بحجم Storage أو RLS أو فشل المصادقة. لقطة المستخدم تؤكد جاهزية الواجهة والقائمة فقط، ولا تتضمن رسالة الخطأ الخاصة بمحاولته؛ لذلك نتعامل مع هذا بوصفه عطل نشر مؤكدًا يمنع أي تصدير يصل إلى استيراد المكتبة، دون ادعاء استبعاد كل سبب إضافي محتمل.

في Service Worker السابق، كان الملفان ضمن قائمة Core الإلزامية. روتين install يرفض نجاح تخزين Core عند 404؛ يمكن لهذا أيضًا منع تفعيل العامل الجديد. تمت معالجة القائمة في هذا التصحيح دون تغيير منطق الكاش أو حذف تخزين المستخدم المحلي.

هذه مشكلة تجهيز في الإصدار الذي سلمناه، وليست حذفًا أو رفعًا ناقصًا من المستخدم. لم تُنفذ أي تغييرات Production أثناء التشخيص والتجهيز؛ طلبات الفحص اقتصرت على ملفات واجهة عامة في GitHub ومستودع المصدر.

## Baseline وScope

Baseline: 18.56.145 / Build 185745 / AM1R1، آخر حزمة معتمدة والمنشورة فعليًا. تمت مطابقة كل ملفات الاستبدال مع النشر قبل العمل. SQL/Deno/خدمات المال/الرواتب/الفواتير/العمولات وP3/P4/P5/SC1 ليست ضمن التعديل.

المطلوب: استعادة سلسلة تحميل مكتبة PDF. الإضافة في القاعدة تظل مفعّلة للعرض والتصدير فقط حسب آخر نتيجة المستخدم، والمسح مغلق. البروتوكول/runtime الخاص بالمرفقات يظل AM1R1؛ الإصدار العام يصبح 18.56.146.

## Minimal Change

| الملف | التغيير |
| --- | --- |
| assets/vendor/noble-hashes-2.0.1/sha2.js | تعديل importين إلى md.js وu64.js فقط |
| assets/vendor/noble-hashes-2.0.1/md.js | نسخة بايتية مطابقة لـ_md.js السابق |
| assets/vendor/noble-hashes-2.0.1/u64.js | نسخة بايتية مطابقة لـ_u64.js السابق |
| service-worker.js | قائمة المسارين الجديدين وCache Token جديد؛ أجسام الدوال كما هي |
| assets/js/pwa.js | CURRENT_VERSION فقط إلى 18.56.146 |
| index.html | إصدار رابط pwa.js فقط |
| package.json وversion.json | إصدار 18.56.146 / Build 185746 ووصف الإصلاح |

الملفات القديمة تبقى في المصدر، فلا يوجد طلب حذف ملفات أو تغيير عام لإعدادات النشر. التنفيذ الفعلي لمكتبة SHA-256 وترخيصها محفوظان. لا نوسع الوصول، ولا نغير فحص نسخة الصورة أو بصمة الأصول أو حدود الذاكرة أو منطق حساب الشهر أو الأرشفة أو المسح.

## Impact Analysis

كل أثر Runtime محصور في وصول وحدات PDF عبر مسارات يمكن نشرها، وتحديث كاش PWA لكي يطلبها. الملفات المالية وواجهات الأعمال ومصفوفة الصلاحيات ودوالها محفوظة بايتًا. لا CSS جديد أو تغيير RTL/LTR أو حركة مستخدم قائمة. سجل المرفقات في Supabase والدالة attachment-admin لا يحتاجان إعادة تثبيت أو نشر.

التصحيح مهم للتصدير وكذلك التحقق من بصمة الملف المحفوظ لأن الاثنين يحملان نفس وحدة PDF. تأثيره على التصدير محدود باستعادة الاستيراد، وليس اعتماد الملف للمسح تلقائيًا. لا يطلب رفع صور أو PDF إلى Storage ولا يغير استهلاك مساحة الأصول.

## ترتيب التنفيذ وSQL

Commit احتياطي 145 → رفع ملفات الحزمة إلى GitHub بنفس المسارات → انتظار نشر Pages → التأكد من 146 → اختبار المعاينة ثم تصدير شهر مغلق وحفظه والتحقق منه. لا SQL مطلوب في هذه المرحلة. لا Migration جديدة، ولا تشغيل 02/04، ولا تغيير Verify JWT أو مفاتيح المشروع، ولا نشر جديد للدالة.

الشهور الكبيرة تحتاج متصفح كمبيوتر يدعم اختيار ملف وحفظًا مباشرًا إلى القرص. نوفمبر الحالي غير متاح للتصدير قبل نهايته بتوقيت الرياض، وفق منطق AM1R1 دون تغيير. حد Blob السابق 100 MiB أصول/200 MiB PDF لم يتغير. لا يحل هذا التصحيح قيود متصفح مختلف أو حظر File Picker مؤسسي إن وُجد؛ نلتقط رسالة الحالة أولًا إذا ظهر سبب آخر.

## Regression المنفذ وحدوده

اختبارات محلية تنفذ استيراد وحدات ESM الفعلية عبر HTTP وخادم يطبق قاعدة استبعاد الأسماء، مع إعادة إنتاج فشل الاستيراد القديم ثم تحميل سلسلة الاعتماديات بعد التصحيح. لا يمثل الخادم بناء Jekyll كاملًا أو متصفحًا أصليًا. اختبار SHA-256 ومطابقة تدفق الملف مقابل Node crypto، ومطابقة بايتات النسخ الجديدة مع الأصل، وبلوغ كل أصول Core الإلزامية في النموذج، واتساق إصدار الكاش.

اختبارات AM1R1 الوظيفية وP3/P4/P5/SC1 يعاد تشغيلها دون تعديل ملفاتها. تستثنى اختبارات أرقام إصداراتها التاريخية بالاسم فقط، ويغطي AM1R2 الإصدار الجديد. تستمر اختبارات RLS/Triggers المحلية كمحاكاة ولا تتحول إلى إثبات لسياسات الحسابات الحية.

تُنشأ ملفات PDF تجريبية عربية وإنجليزية، وتُراجع الصفحات بصريًا ويُختبر استخراج الأصول ومطابقة بصماتها. بايتات الملفات التجريبية تقارن بمخرجات AM1R1 المحلية لإثبات بقاء حساب البصمة ومحتوى PDF كما هما. القيم النهائية وعدد الاختبارات في TEST_RESULTS.json.

مطلوب بعد النشر: 200 ومسار JavaScript صحيح لكل من md.js وu64.js، اكتمال تحديث PWA، معاينة صورة حقيقية، تصدير شهر مغلق وحفظ الملف، فحص الصفحات والبيانات والأصول، الحسابات غير المصرح لها، Desktop/Tablet/Mobile والعربية/الإنجليزية والفاتح/الداكن. الاختبارات المحلية واللقطة الحالية لا تثبت نجاح PDF الخاص بالمستخدم. لم تُختبر عملية حذف أو تشغل، وتظل متوقفة.

## Rollback

تراجع Commit هذا التصحيح إلى 145. لا يوجد SQL Rollback لأن القاعدة والدالة والسياسات لم تتغير. راجع آلية PWA للتأكد من تحميل النسخة المختارة، مع الاحتفاظ بـIndexedDB وبيانات العمل المحلية. سيعود عطل الاعتماديات القديم إذا عاد الكود القديم. لا يستلزم تراجع واجهة تحميل المكتبة أي حذف لأرشيف أو أصول أو أقفال في القاعدة.

أقفال التصدير السابقة تتبع منطق AM1R1: تحرير عند نجاح/إلغاء العملية، أو انتهاء مهلة التصدير عند فقد الاتصال. إذا بقيت حالة غير متوقعة، استخدم فحص الأرشيف Read-Only من المرحلة السابقة، ثم عالج السبب المثبت؛ لا نمسح سجلات أو أقفالًا كجزء من هذا التصحيح.

## المخاطر المتبقية

يجب رفع الملفين الجديدين مع التعديلات؛ تغيير رقم الإصدار وحده لا يكفي. يجب انتظار اكتمال النشر وتفعيل الكاش الجديد. يمكن أن يظهر لاحقًا خطأ مختلف متعلق بملف صورة أو دعم API القراءة المقيدة بالنسخة أو إعداد المتصفح؛ لا يُلغى فحص النسخة أو يُفعّل المسح لمعالجته. اختبارات الإنتاج للصور الفعلية والحسابات والأجهزة ما زالت مطلوبة قبل اعتماد التصدير أو تفعيل المسح. ملفات SQL والسياسات والدوال القديمة لم تتغير.
