# تقرير AM1R1 — 18.56.145 — جاهزة للمراجعة والتثبيت المعطل

## Root Cause

المرفقات موزعة على Storage وجداول مصادر مختلفة، دون شاشة تجميع أو أرشيف شهري يربط PDF بالأصول الموجودة فيه. حزمة AM1 السابقة غير المثبتة افترضت أن updated_at يدل على استبدال المحتوى، بينما نتائج Production أثبتت وجود Trigger يغيره عند UPDATE. كما لم تكن تستبعد الصفوف المؤرشفة/Delete Markers أو تثبت HTTP القراءة والحذف على رقم نسخة المحتوى. أصلحنا هذه الافتراضات قبل أي تثبيت؛ لا ندعي وقوع خطأ إنتاج من الحزمة غير المنشورة، ولا أن HTTP القراءة يغير التوقيتات بالفعل.

## Baseline وScope

18.56.144/185744، مبنية على آخر ZIP والتعديلات المعتمدة P3/P4/P5/SC1. الملفات السبعة التي ستُستبدل طابقت النشر الحي بتاريخ 2026-11-09؛ بصماتها في SOURCE_INTEGRITY.json. الحزمة Modified Files Only؛ تشمل الواجهة الجديدة، Edge جديدة، Migration واحدة معطلة، أدوات تحقق وتراجع واستخراج، دون تغيير خدمات المال أو السياسات والدوال القديمة. تحذيرات Security Advisor السبعة المتبقية وملاحظات توقيت P5 ليست مغلقة بهذه المرحلة.

## أدلة Production وحدودها

النتائج المرسلة من المستخدم `am1_precheck` عند 06:44:18Z و`am1_storage_semantics_audit` عند 07:22:23Z في 2026-11-09 هي أدلة كتالوج قراءة فقط. ليست اختبار Storage API أو حسابات أو حذف، وليست تفويضًا للمسح. الملخص في PRODUCTION_AUDIT_20261109.json. كل المخازن خاصة وSTANDARD وVersioning=DISABLED، وكل 425 صورة لها نسخة physical version؛ لا نفعل Versioning ولا نفترض أن وجود العمود يثبت دعم كل API في بناء الخدمة المنشور.

423 صورة تركيب: 390 مرتبطة بسجل واحد و33 بلا سجل مطابق. صورة مصروف SEA VIBE مرتبطة مع fallback لمالك Storage بدل رافع غير مسجل، وصورة واتساب شخصية محمية. لا نعتبر الـ33 صورًا بلا استخدام أو نربطها بالعميل من الاسم. قيم الحجم Metadata وليست Billing. أعداد الشهور السابقة مبنية على تواريخ الصفوف، وقد تختلف عن وقت المحتوى عند حدود الشهور.

## التغيير الأدنى وأمان الوصول

Schema خاصة petatoe_am1 بخمسة جداول RLS بلا سياسات متصفح، وRPC واحدة service_role فقط. وظائف Schema الخاصة محجوبة عن PUBLIC/anon/authenticated، مع search_path=pg_catalog ومراجع مؤهلة. كل طلب يتطلب مستخدم Auth صحيحًا وprofile نشطًا بدور super_admin؛ actor يؤخذ من getUser على السيرفر وليس JSON المستخدم. الشاشة الجديدة وصف صلاحياتها للمدير فقط، دون تعديل أي دور قائم أو السياسة القديمة.

تتطابق مراجعة Edge/UI/SQL على AM1R1، ويمنع عدم التطابق الوصول. SDK الإضافة ثابتة على supabase-js 2.119.0 في Edge فقط. المفتاح الإداري لا يخرج للواجهة أو المستودع؛ Origin مضبوط، والردود لا تسرب SQL أو أسرارًا. الروابط الموقعة للمدير قصيرة العمر، ولا تدخل PDF/Logs. إبقاء Verify JWT شرط للنشر.

Trigger جديد واحد يحمي مسارات اللقطة نفسها دون افتراض دور تنفيذ Storage الداخلي. كل كتابة محتوى/نقل/إعادة إنشاء لهذه المسارات تتوقف خلال القفل؛ تحديث updated_at/last_accessed_at فقط يظل مسموحًا. أثناء المسح يسمح بالـDELETE المطابق لـID والنسخة والمسار واللقطة المؤكدة التي سبق إرسال طلبها فقط. لا يمنح صلاحية ولا يتجاوز RLS أو Trigger protect_objects_delete. لا يتغير أي Trigger منصة أو GUC حذف. لا تمس مسارات أخرى.

هذا قد يوقف مؤقتًا استبدال صورة قديمة داخل اللقطة برسالة AM1_OBJECT_ARCHIVING؛ الرفع لمسار جديد غير مقفل لا يتأثر. يلزم اختبار ذلك فعليًا قبل المسح. تعديل البنية المدارة يحتاج مراجعة مع تحديثات Supabase؛ مالك SQL يستطيع تعطيل Trigger عمدًا، وهذا خارج ضمان الإضافة ويجب ألا يحدث أثناء عملية أرشفة/مسح.

## سلامة الوقت والنسخة والأرشيف

نستبعد archived_at وDelete Markers من قائمة الصور الحالية، ونرفض أرشفة وضع غير STANDARD/DISABLED أو صف is_versioned=true. الوقت هو lastModified بتنسيق ISO وتوقيت واضح، ثم created_at كبديل معلن، وليس updated_at. بصمة الحالة تتجاهل توقيتي bookkeeping فقط وتحتفظ بـID والمسار ونسخة المحتوى والمالك وMetadata وحالة الصف.

يوقع السيرفر URL بـversionId، ويفحص أن token القادم من SDK يحدد نفس النسخة والمسار ومضيف المشروع. فحص payload هنا إثبات Binding من مصدر موثوق، وليس مصادقة رمز وارد من المستخدم؛ المصادقة منفصلة بـAuth. خدمة تتجاهل versionId لا يمكنها اعتماد PDF؛ لا يوجد fallback غير مقيد. يُسجل version_bound_at، ويُشترط لكل أصل عند اكتمال الأرشيف.

PDF واحد للشهر المغلق بتوقيت الرياض، صفحة لكل صورة والبيانات، وصورة أصلية كاملة وJSON لكل أصل كمرفقات داخل PDF. القراءة متدرجة صورة واحدة والكتابة مباشرة للقرص عند الدعم. البصمة SHA-256 للمحفوظ تطابق الإيصال قبل confirm. المتصفح لا يثبت وجود نسخة ثانية؛ الإقرار مسؤولية المدير. لا يحفظ السيرفر PDF، ولا يخفض التصدير مساحة Storage وحده.

## الحذف والتزامن وعدم اليقين

المسح مغلق مبدئيًا وبقرار تفعيل منفصل بعد اختبارات الإنتاج. كل طلب Edge يعالج خمسة أصول كحد أقصى، مع Mutex للدفعة وأقفال مسارات لا تنتهي تلقائيًا أثناء حذف غير محسوم. Storage API تستقبل [{path, versionId}] من اللقطة المؤكدة فقط، ولا يرجع التنفيذ إلى اسم مجرد مهما كان الخطأ. إعادة التحقق تستهدف نفس ID/النسخة؛ لا تطلب إزالة نسخة بديلة أحدث. الصفوف المالية وصفوف المرفقات والعملاء لا تحذف ولا تعدل.

الـ4xx المؤكدة من Storage تسمح بمحاولة يدوية بعد حل السبب. أخطاء الشبكة و5xx و408 و499 تظل غير محسومة، ولا يُعاد إرسال remove لنفس الملف تلقائيًا. عند غياب النسخة القديمة بعد نجاح سابق وفقد الرد يمكن تسوية السجل دون إزالة أخرى. بقاء الأصل مع نتيجة غير محسومة يوقف المسار ويستدعي مراجعة الطلب السابق، لا تصفير flags أو حذف الأقفال.

لا يوجد SQL DELETE على storage.objects ولا تخطي protect_delete؛ المحاكاة المحلية فقط تضع GUC في معاملات اختبار Storage API. دعم جسم طلب exact-version الفعلي على الإنتاج واختبارات التزامن ما زالا مطلوبين؛ لا نعتمد نجاح SDK محليًا كدليل نشر الخدمة. أي رفض يتوقف دون fallback بالمسار.

بعد المسح يتوقف رابط الأصل القديم داخل الشاشات القائمة؛ البيانات والسجلات تبقى سليمة، لكن فتح الصورة يتطلب PDF أو استرجاع أصلها لنفس المسار. هذا أثر حذف مقصود يجب قبوله قبل التفعيل؛ لم نغير منطق الشاشات القديمة كي تقرأ قرص المستخدم أو الحسابات المالية.

## ترتيب التنفيذ وRollback

التفصيل في README_AM1_AR.md. الآن: Backup مناسب → Migration الجديدة معطلة → 01 قراءة فقط ومراجعة. بعد النجاح: نشر Edge والتحقق من ACL/Origin/Auth → نشر الواجهة → 02 عرض/أرشفة فقط → اختبار PDF فعلي واسترجاع أصول ونسخة ثانية → 03 تحقق. 04 خطوة مستقلة لاحقة وليست جزءًا من النشر الأول. لا تُنفذ كل ملفات SQL كدفعة واحدة.

قبل المسح، 05 يعطل الإضافة ويبقي تاريخها، ثم الرجوع إلى Commit واجهة 144. لا DROP/CASCADE. عند أقفال حذف غير محسوم، 05 يرفض إزالة الحماية؛ 06 يوقف طلبات جديدة ويحتفظ بالأقفال والتاريخ، وقد يكمل طلب قد بدأ بالفعل. راجع Logs و03 وStorage قبل استكمال موثق. لا تعطل Trigger أو تمسح الأقفال لمعالجة رسالة خطأ.

SQL Rollback لا يعيد الصور المحذوفة. نسخة قاعدة البيانات ليست نسخة أصول Storage. نسخة مستقلة مناسبة قبل المسح + نسختا PDF، والاستخراج محليًا بواسطة am1-extract-archive.py يتحقق من SHA-256 ويرفض الكتابة فوق ملفات موجودة ومسارات غير آمنة. الاستعادة عبر Storage API بعد مراجعة عدم وجود نسخة أحدث؛ صفوف الأعمال لا تتغير. هوية النسخة المسترجعة جديدة، فلا يجيز إيصال قديم مسحها.

## الاختبارات والمخاطر المتبقية

TEST_RESULTS.json يسجل الاختبارات المنفذة وحدودها. اختبارات PostgreSQL معزولة وتشمل شكلي Trigger protect_delete وupdate_updated_at الفعليين وحقول Versioning والفهارس الحالية؛ نموذج RLS العام فيها Fixture فقط وليس نسخة من سياسات الإنتاج. اختبارات Edge تستخدم Auth/Storage محاكاة وSDK الحقيقية، واختبارات DOM ليست اختبار عرض متصفح أصلي. ملفات PDF عربية/إنجليزية تجريبية تُفحص بصريًا وتستخرج أصولها وتطابق بايتاتها.

مطلوب على Production قبل المسح: مدير/موظف محدود/مندوب/بدون تقارير/anon، الوصول المباشر ورفضه، الصور وبياناتها وصحة عميلها ورفعها ووقتها، حالات تغيير الصورة/انقطاع الطلب/إيقاف العملية/الحساب، الرفع والتعديل خارج اللقطة وداخلها، العربية/الإنجليزية وRTL/LTR وDesktop/Tablet/Mobile، PDF للشهر الكبير والاسترجاع والنسخة الثانية، بقاء سجلات الأعمال بعد دفعة الحذف الأولى. نجاح SQL أو HTTP 200 أو عدد صفر لا يغلق هذه الاختبارات.

حدود التنفيذ: 5,000 صورة/2 GiB أصول/4 GiB PDF؛ Blob fallback محدود بـ100 MiB أصول و200 MiB PDF. الصيغ غير المدعومة/الأبعاد الكبيرة/البيانات الأطول من صفحة توقف الأرشيف دون اعتماد جزء منه. PDF يتضمن بيانات حساسة ويحتفظ به المدير. لا يعرف الكود رافعًا أو عميلًا لم يسجل تاريخيًا. لا اختبار حذف أو تزامن أو أجهزة على الإنتاج من جهتنا.
