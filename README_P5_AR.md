## قبل الرفع

1. احتفظ بنسخة من commit GitHub الذي يعمل عليه الإصدار `18.56.142`، أو نزّل ZIP منه. احتفظ بالملفات الثمانية الأصلية المذكورة أدناه للتراجع.
2. طابق نسخة المشروع الحالية مع الأساس. من **مجلد الحزمة المفكوك**، إن كان Node متاحًا:

   ```bash
   node scripts/p5-finance-preflight-check.mjs baseline /absolute/path/to/current-app
   ```

   الفحص محلي للملفات الثمانية المستبدلة و12 ملفًا مرتبطًا، ولا يفحص المستودع كله. إذا ظهر `FAIL`، يجب مراجعة النسخة الأحدث قبل استبدال الملفات. ظهور رقم `18.56.142` وحده لا يثبت تطابق الكود.
3. هذه المرحلة لا تحتاج تشغيل SQL أو تغيير قاعدة البيانات؛ النسخة الاحتياطية المطلوبة لها هي نسخة الكود السابقة. لا يوجد ملف Apply أو Rollback لقاعدة البيانات ضمن الحزمة.

## بعد اكتمال النشر

1. أعد تحميل التطبيق بالطريقة المعتادة، وتأكد من ظهور `18.56.143` في «حول التطبيق». لا تستخدم Clear site data أو تمسح IndexedDB / localStorage، لأنها قد تحتوي عمليات Offline Queue لم تُزامن بعد.
2. على الداشبورد، شغّل محتوى `scripts/p5-visible-finance-live-readonly.js` في Console. الالتقاط فوري ومحلي؛ لا يرسل HTTP أو RPC ولا يشغّل المزامنة. احفظ الناتج الأول.
3. افتح خزينة السيارة ثم إدارة الرواتب ثم ارجع للداشبورد، وانتظر اكتمال القراءات التي بدأت أثناء الفتح. التقط الناتج مرة أخرى ليكون نقطة المقارنة. انتقل لتبويب آخر ثم عُد، وكرر الالتقاط بعد استقرار الطلبات.
4. المتوقع على الداشبورد: `runtime: "P5"` للخدمات الثلاث، و`eligible: false`، وعدم زيادة `refreshCalls` فيها خلال أحداث العودة للتبويب. قد تزيد `invocations` لأن محرك المزامنة ينادي المهمة ثم ترفض القراءة. قناة الإشعارات تبقى مستقلة، وقناة التنفيذ تكون صفرًا أثناء الداشبورد وفق P4.
5. استخدم Network خلال **فترة مستقرة على الداشبورد** للتأكد من عدم بدء طلبات workspace المالية المستهدفة بفعل الرجوع للتبويب/الاتصال. لا تحتسب طلبات بدأت عند فتح الشاشات ثم انتهت لاحقًا على الداشبورد. تفاصيل أسماء الـRPC واختبارات الحسابات واللغات والأجهزة في التقرير.

`refreshCalls` عداد استدعاء مسار التحديث التلقائي، وليس عداد HTTP أو نجاحًا أمنيًا. القيم تتصفّر عند إعادة تحميل الصفحة. لقطة واحدة لا تثبت تسلسل الانتقال أو خفض الاستهلاك.
