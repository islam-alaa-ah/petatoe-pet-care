# PETATOE — P4: اتصال شاشة تنفيذ المواعيد

الإصدار المجهز: **18.56.142 / Build 185742** — 8 نوفمبر 2026.

هذه حزمة Modified Files Only مبنية على مصدر 18.56.141 مع P3 المنشور والمؤكد. لم ينشر المساعد هذه الحزمة على Production.

## ماذا تعالج؟

اشتراك تحديث تنفيذ المواعيد يعمل أثناء فتح شاشة التنفيذ وظهور التبويب للحساب المسموح. عند المغادرة أو الإخفاء أو الخروج يُغلق اشتراك التنفيذ ويُلغى تحديثه المعلق. عند الرجوع تُطلب قراءة حديثة، مع استخدام الكاش المتاح إذا كانت الشبكة غير متاحة أو فشلت القراءة. تُرفض نتائج القراءة المتأخرة من جلسة شاشة أو مستخدم سابق.

هذه الخطوة لا تعالج جميع تحميلات محرك المزامنة؛ قد تستمر قراءة سياقات سبق فتحها عن طريق Sync Engine. الإشعارات P3 والمزامنة والمهام والرواتب وخزينة السيارة لها مساراتها الحالية. لا SQL مطلوب، ولا تغيير RLS أو أدوار أو حسابات مالية.

## قبل الرفع

1. احفظ مرجع آخر commit/نسخة **18.56.141** المنشورة، والملفات التشغيلية السبعة التالية لاستعادتها عند الحاجة.
2. تأكد أن المشروع لم يتلق تعديلًا أحدث من 18.56.141 في هذه الملفات. إذا يوجد تعديل أحدث، يجب الدمج عليه قبل استبدالها.
3. فحص البصمات الاختياري أدناه يقارن الملفات فقط ولا يعدّلها. الحزمة لا تمثل Backup للقاعدة، ولا تنفذ أي تغيير عليها.

```bash
node scripts/p4-preflight-check.mjs baseline /absolute/path/to/current-app
```

## الرفع إلى GitHub

ارفع **محتويات مجلد P4-Execution-Realtime** إلى جذر المشروع، بالمسارات نفسها، ويفضل في commit واحد. لا ترفع مجلد المرحلة كطبقة إضافية فوق جذر التطبيق، ولا تستبدل المشروع كله بنسخة قديمة.

الملفات التشغيلية المعدلة هي:

```text
assets/js/installation-execution.js
assets/js/installations-service.js
assets/js/pwa.js
index.html
package.json
service-worker.js
version.json
```

بقية الملفات السبعة المضافة هي التقرير ونتائج الاختبارات والبصمات وثلاث أدوات فحص محلية؛ لا تُحمّل أدوات الفحص تلقائيًا بواسطة index.html. لا migrations أو ملفات SQL ضمن الحزمة.

بعد النشر استخدم مسار تحديث التطبيق المعتاد، وتحقق من **18.56.142** في «حول التطبيق». ملفات JS/CSS التي لم تتغير تحتفظ بعلامات الكاش السابقة؛ تم تحديث علامات الملفات الثلاثة المعدلة في index فقط، ورقم كاش Service Worker.

## فحص بسيط بعد النشر

الصق `scripts/p4-execution-live-readonly.js` في Console مرة واحدة لكل حالة، ثم `copy($_)` مباشرة لنسخ النص:

| الحالة بعد استقرار الاتصال/الإغلاق | المتوقع |
|---|---|
| Dashboard | runtime=P4، execution=0، active=false |
| شاشة التنفيذ، حساب مسموح، online والتبويب ظاهر | execution=1، active=true، executionStates تشمل joined عند اتصال Realtime |
| الرجوع إلى Dashboard | execution=0 بعد اكتمال الإغلاق، والإشعارات تستمر حسب حالة الحساب والاتصال |
| إخفاء التبويب ثم الرجوع إلى التنفيذ | إغلاق القناة أثناء الإخفاء، ثم قناة واحدة وقراءة مصالحة عند الرجوع |
| الخروج أو حساب بلا صلاحية التنفيذ | لا قناة تنفيذ ولا بيانات تنفيذ من الحساب السابق |

السكربت قراءة من الذاكرة فقط؛ لا HTTP/RPC أو حفظ أو قنوات جديدة، ولا يعرض IDs أو Tokens أو أسماء عملاء أو قنوات تتضمن هوية. اللقطة لحالة واحدة لا تثبت نجاح كل الانتقالات.

لا تنشئ فاتورة أو تحصيلًا أو انتقالًا ماليًا تجريبيًا لأجل الفحص. افتح بيانات موجودة ومسموحًا بها، وراجع القوائم والنطاق والترجمة. لا تستخدم Clear Site Data أو تمسح IndexedDB/localStorage؛ قد توجد عمليات Offline Queue لم تُزامن.

## التراجع

إذا ظهر عطل مرتبط بهذه الخطوة، أعد commit هذه المرحلة وحده أو استعد الملفات التشغيلية السبعة من آخر نسخة 18.56.141 المعتمدة، مع الحفاظ على أي عمل أحدث. بعد نشر التراجع أغلق تبويبات التطبيق القديمة وافتح الصفحة مع تحديث المتصفح؛ تحقق من رجوع runtime/الإصدار السابق. خفض رقم manifest وحده لا يضمن أن التبويب المفتوح سيعيد تحميل نفسه تلقائيًا.

لا SQL للتراجع، ولا إعادة تشغيل migrations، ولا تراجع عن إصلاحات Security المطبقة. قد تعود قناة التنفيذ الخلفية بعد التراجع لأنها السلوك السابق.

التفاصيل والاختبارات والمخاطر: `docs/P4-execution/IMPACT_AR.md`.
