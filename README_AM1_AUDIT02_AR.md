# AM1-AUDIT-02 — مراجعة نتيجة Production

الحالة: **تعليق تثبيت حزمة AM1 18.56.145 السابقة لحين استكمال مطابقة Storage**. النسخة المنشورة التي أعيد فحص رقمها هي 18.56.144 / Build 185744.

النتيجة المرسلة بتاريخ 09/11/2026 الساعة 08:44 بتوقيت القاهرة أكدت وجود الجداول المطلوبة، وأن Buckets الخمسة خاصة، وعدم وجود Schema أو RPC أو شاشة AM1 بعد. لكنها أظهرت Trigger يغيّر `updated_at` مع كل UPDATE، وأعمدة لنسخ الملفات وحالات الأرشفة والحذف لم تكن ممثلة في الاختبارات المحلية الأولى.

## الخطوة الآن

شغّل **هذا الملف فقط** في SQL Editor:

`docs/AM1/sql/00B_STORAGE_STATE_READONLY.sql`

ثم أرسل نتيجة `am1_storage_semantics_audit`. الاستعلام يجمع حالة النسخ، مقارنة التواريخ، تغطية ربط الصور بالمستخدم والعملية والعميل، وبيانات الحماية والفهارس. لا ينشئ أي كائن، ولا ينفذ RPC أو Storage API، ولا ينزل أو يحذف صورة، ولا يعيد أسماء عملاء أو أرقام هواتف أو مفاتيح.

لا تشغّل Migration السابقة أو ملفات التفعيل، ولا ترفع ملفات الواجهة لهذه المرحلة. هذه الحزمة إضافة فحص فقط؛ لا تحتوي استبدالًا لأي ملف من البرنامج. لا تُرفع ملفاتها إلى GitHub لتشغيل الشاشة.

إذا انتهى الاستعلام بخطأ، نفّذ `ROLLBACK;` لإغلاق المعاملة إن بقيت مفتوحة، ثم أرسل الخطأ. لا تكرر الاستعلام تلقائيًا ولا تغيّر إعدادات حماية Storage.

## ما ثبت وما ينتظر

- تم إثبات التداخل محليًا باستعمال تعريفَي Trigger اللذين أرسلتهما: تحديث `last_accessed_at` فقط يغيّر `updated_at` ويجعل البصمة القديمة ترفض إكمال الأرشيف.
- **لم يثبت** أن طلب قراءة صورة عبر Storage API عندك ينفذ ذلك التحديث. المثال المحلي يكشف حالة يجب دعمها، وليس وصفًا لحادث وقع على Production.
- وجود أعمدة Versioning **لا يثبت تفعيل Versioning أو وجود نسخ قديمة**. الاستعلام التكميلي يحدد الحالة الفعلية للـBuckets والصفوف.
- العد الأول هو 425 سجل صورة بحجم مسجل 1,107,194,388 بايت. عدد الصور الحالية الفريدة، وتغطية بيانات الرافع والعميل، يحتاجان النتيجة التكميلية. الحجم المسجل ليس قياس الفوترة أو دليلًا على سبب فقد الاتصال السابق.
