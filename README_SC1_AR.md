# PETATOE — SC1: استعادة اتصال SmartCache المحلي

**الأساس:** `18.56.143 / 185743`. **الإصدار الناتج:** `18.56.144 / 185744`.

حزمة Modified / Added Files Only: ستة ملفات قائمة معدلة وثمانية ملفات مضافة، داخل مجلد مرحلة واحد. الملف التشغيلي المستهدف هو `assets/js/smart-cache.js`؛ باقي تعديلات التشغيل لرقم الإصدار وتحميل النسخة الصحيحة فقط.

الإصلاح يعالج استمرار استخدام اتصال IndexedDB مغلق، وهو سبب تكرار أخطاء `The database connection is closing` في SmartCache. اسم قاعدة الكاش ونسخة schema والبيانات والتقسيم حسب المستخدم تظل كما هي. لا يلزم SQL لهذه المرحلة.

## قبل الرفع

1. احتفظ بـcommit أو ZIP النسخة الحالية `18.56.143`، وبالأخص الملفات الستة أدناه، لخطة التراجع.
2. إذا أجريت أي تعديلات أخرى بعد 18.56.143، راجع تطابقها قبل استبدال الملفات. جرى فحص الملفات الستة المنشورة ومطابقتها قبل إعداد هذه الحزمة؛ لم تُراجع نسخة متصفحك المحفوظة بايتًا ببايت.
3. من مجلد الحزمة المفكوك، يمكن فحص نسخة المستودع الحالية محليًا:

   ```bash
   node scripts/sc1-preflight-check.mjs baseline /absolute/path/to/current-app
   ```

   يفحص الملفات الستة المستبدلة والملفات المرتبطة المسجلة في التقرير، وليس المستودع كله. أي `FAIL` يحتاج مراجعة النسخة الأحدث قبل النسخ.

## بعد اكتمال النشر

1. أعد تحميل البرنامج بالطريقة المعتادة وتأكد من ظهور `18.56.144` في «حول التطبيق».
2. شغّل محتوى `scripts/sc1-live-readonly.js` في Console. النتيجة تظهر مباشرة كنص يبدأ بـ`SC1_RESULT`؛ انسخ JSON المطبوع. الالتقاط لا يفتح قاعدة IndexedDB ولا ينفذ HTTP أو RPC أو يغير البيانات.
3. المتوقع عند استخدام التطبيق بعد تحميل البيانات: `cacheRuntime: "SC1"`، و`cacheConnection.state: "open"`، و`schemaVersion: 1`. وجود رقم الإصدار الجديد وحده لا يكفي إذا كانت نسخة SmartCache القديمة لا تزال محملة.
4. تأكد من `configured: true` و`clientReady: true` و`authOffline: false` أثناء الاتصال الطبيعي، ومن عدم تكرار أخطاء closing connection الجديدة أثناء التنقل والعمل المعتاد. فرّق بين الرسائل القديمة المحفوظة في Console والرسائل التي تظهر بعد النشر.
5. تحقق من عرض بيانات معروفة، ثم العرض offline بعد تحميلها، ثم العودة online، وعزل البيانات عند تبديل الحساب المصرح به. لا تنشئ عمليات مالية تجريبية ولا تمسح بيانات الموقع لاختبار التعافي.

لا تستخدم Clear site data أو حذف IndexedDB أو تعديل رقم نسخته بهدف الاختبار؛ قد توجد بيانات Offline Queue لم تزامن. محاكاة الإغلاق القسري أجريت على قاعدة وهمية معزولة في الاختبارات المحلية فقط.
