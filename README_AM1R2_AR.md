# AM1R2 — إصلاح تنزيل PDF المرفقات — 18.56.146 / Build 185746

حزمة **Modified Files Only** فوق آخر نسخة منشورة **18.56.145 / AM1R1**. ملفات الاستبدال الستة طابقت النسخة المنشورة قبل تجهيز التصحيح. الحزمة لا تحتوي SQL ولا ملفات Edge جديدة، ولا تعدل أي صلاحية أو حساب مالي.

## السبب المؤكد

المكتبة `sha2.js` متاحة من الموقع المنشور، لكنها تستورد `_md.js` و`_u64.js`. الملفان موجودان داخل مستودع GitHub وبنفس بايتات حزمة AM1R1، لكن طلبهما من GitHub Pages يرجع 404. إعداد النشر الافتراضي لـJekyll يستبعد الأسماء التي تبدأ بـunderscore؛ وهذا يمنع تحميل وحدة PDF أصلًا، حتى مع سلامة تسجيل الدخول والقائمة والدالة.

كانت هذه مشكلة تجهيز في حزمة AM1R1، وليست خطأ في رفع المستخدم ولا سببًا لتغيير صلاحيات Supabase. توقف استيراد المكتبة قبل توليد PDF عطل مؤكد، وقد نحتاج معالجة سبب آخر فقط إذا ظهر بعد الوصول للخطوة التالية من التصدير.

## ما تغير

- نسختان مطابقـتان بايتًا للملفين باسمين صالحين للنشر: `md.js` و`u64.js`.
- تعديل سطري import في `sha2.js` فقط، دون تغيير تنفيذ SHA-256 أو ترخيص المكتبة.
- تحديث قائمة ملفات Service Worker والكاش إلى إصدار 146 لضمان تحميل الاعتماديات الصحيحة. سلوك Service Worker نفسه لا يتغير.
- تحديث رقم الإصدار وملف PWA والرابط الخاص به داخل index.html فقط.
- أداة تشخيص محلية إضافية تعرض شهر التصدير ورسالة الشاشة ودعم نافذة الحفظ دون طلبات شبكة.

`attachmentRuntime: AM1R1` بعد التحديث **متوقع وصحيح**؛ تعديل AM1R2 يخص نشر ملفات PDF فقط، وبروتوكول الدالة وقاعدة البيانات يظل AM1R1.

## التنفيذ — GitHub فقط

1. احتفظ بالـCommit الحالي للواجهة 18.56.145 للتراجع.
2. فك الحزمة وافتح مجلد `AM1R2-PDF-Delivery-Fix`. ادمج **كل محتوياته** بجذر مستودع المشروع بنفس المسارات. يحتوي التصحيح 6 ملفات معدلة وإضافات محددة، وليس نسخة مشروع كاملة. احتفظ بباقي ملفات المشروع وبالملفات الأصلية القديمة للمكتبة.
3. انتظر اكتمال GitHub Pages، ثم حدّث البرنامج وفق آلية التحديث المعتادة. المطلوب ظهور **18.56.146 / 185746**. لا تمسح IndexedDB أو بيانات البرنامج المحلية لتطبيق هذا التصحيح.
4. لا تشغل Migration أو 02 أو 04، ولا تعِد نشر `attachment-admin`. العرض والأرشفة مفعّلان بالفعل حسب آخر نتيجة المستخدم، والمسح يظل `deletion_enabled=false`.
5. افتح «إدارة المرفقات» بحساب المدير، واختبر معاينة صورة. بعدها اختر شهرًا مغلقًا، واضغط «تنزيل PDF الشهر»، وحدد مكان حفظ الملف على الكمبيوتر، وانتظر اكتماله. استخدم Chrome أو Edge على الكمبيوتر للشهور الكبيرة التي تحتاج الحفظ مباشرة للقرص.
6. افتح الملف المحفوظ وراجع الصور والبيانات. تحقق من النسخة المحفوظة داخل الشاشة، ثم استخرج الأصول وافحصها وفق دليل AM1R1. تبقى مراجعة النسخة الثانية ونطاق الحذف واختبارات الحسابات مطلوبة قبل أي تفعيل للمسح.
7. إذا توقف التصدير، ابق في الشاشة وشغل محتوى `scripts/am1r2-pdf-readonly.js` داخل Console، وأرسل ناتج JSON فورًا قبل التحديث أو الانتقال. يسجل رسالة الخطأ الحالية والشهر ودعم الحفظ، ولا يعيد التصدير أو يستدعي API أو يطبع Tokens أو بيانات العملاء. نتيجة السكربت تشخيص محلي وليست إثبات نجاح PDF أو الأمان.

## الاختبارات

التقرير والأثر والتراجع في `docs/AM1R2/IMPACT_AND_ROLLBACK_AR.md`. نتائج التنفيذ المحلية في `TEST_RESULTS.json`، وأدلة HTTP السابقة للتصحيح في `DEPLOYMENT_AUDIT.json`، وبصمات الملفات في `manifest.json`.

اختبار الاعتماديات قابل للإعادة محليًا على Node 24:

```bash
node --experimental-vm-modules --test scripts/am1r2-pdf-assets.test.mjs
```

الاختبار يستخدم خادمًا محليًا ومحاكاة لقاعدة استبعاد أسماء الملفات، ولا يتصل بقاعدة Production. نجاحه لا يغني عن التحقق من ظهور المسارات الجديدة ونجاح PDF الفعلي بعد رفع الحزمة.

## التراجع

ارجع Commit الواجهة إلى النسخة المحفوظة 18.56.145، ثم أعد التحميل وفق آلية PWA المعتادة. تراجع Git يعكس ملفات هذا التصحيح فقط؛ لا توجد تغييرات قاعدة تحتاج SQL Rollback. مكتبة PDF القديمة كانت متعطلة على النشر، فيعود هذا القيد عند التراجع. سجلات الأرشفة وقفل المسح في Supabase لم تتغير بهذا التصحيح. لا تُحذف أقفال الأرشفة يدويًا؛ إذا ظهرت رسالة أرشفة جارية أو نتيجة غير محسومة، راجع فحص الأرشيف قراءة فقط من حزمة AM1R1 بدل تغيير السجلات.
